let agents use secrets without seeing them.

àṣírí is Yoruba for "secret". An agent asks for asiri://dev/github, you approve, and asiri hands the value to the command that needs it. The agent gets the result, never the secret.

> Read https://asiri.run/skill.md. From now on, ask me through asiri before using any secret, and never print one.

or set up your vault first

how it works

01storeYou add a secret once. It's typed without echo and sealed in a vault that runs in a container on your machine. asiri ls shows names, never values.
02approveAn agent asks for it by name, with a reason. You answer in Rex, in your terminal, or with asiri approve: once, for 15 minutes, or for an hour.
03useasiri hands the value to the one program allowed to receive it and scrubs it from the output. The agent gets the result.

approve without leaving Rex

Requests appear in Rex's command palette with the secret reference, command, and reason. Allow once, grant a short window, or deny. Your owner profile makes the decision; the agent cannot approve itself.

curl -fsSL https://asiri.run/install.sh | sh

Installs the v0.1.0 binary, checks its checksum, and runs asiri rex install when Rex and an owner profile are already there. Without those, it prints the next command.

what asiri won't do

✗hand a secret to a shell, interpreter or wrapper (sh, python, node, env, sudo, ...). They could send it anywhere. Exit 126.
✗hand it to a program that isn't on the secret's allow-list. Exit 126.
✗let the value reach you or the agent in the output. It, and its base64, hex and URL forms, become [asiri:…].
✗let an SSH key leave the server. The server signs, and only for the hosts you allowed.
✗let an agent approve its own request. The server refuses decisions from agent profiles.

run it

# the server: a container on 127.0.0.1:7420
asiri server keygen -o ~/.config/asiri/master.key
cd deploy && docker compose up -d

# pair this machine, then store a secret
asiri pair --code <code>
asiri add dev/github

# only gh may receive it
asiri policy dev/github --bins gh --max-grant 1h

One Go binary: the server in the container and the CLI on your machine. The vault is SQLite, encrypted with XChaCha20-Poly1305 and a key only you hold. Clients pair over mutual TLS, and every change lands in a hash-chained audit log.
